# Reference

## Contact_harvester

Repository:
https://github.com/Evgen-rus/Contact_harvester

Использовать как архитектурный референс для:
- HTTP-first обхода;
- browser fallback;
- collector/extractor/service separation;
- retry и page limits;
- Playwright;
- устойчивости к ошибке одного домена;
- тестируемости.

Не переносить предметную телефонную логику.

Не изменять Contact_harvester и не превращать LumiMatch в его модуль. Перед изменением сбора изучить релевантную часть референса и реальные сайты затронутых поставщиков; повторно исследовать весь референс для несвязанных задач не требуется.

## Протокол аудита поставщика

Сначала использовать сохранённый [SUPPLIER_AUDIT](SUPPLIER_AUDIT.md), затем актуализировать затронутые домены ограниченной выборкой. Для нового поставщика проверить robots.txt, sitemap/index, HTTP-карточки, JSON-LD/schema Product, OpenGraph/meta, canonical, категории/пагинацию, SKU/название, цену/наличие, характеристики/размеры и фото. Отметить JS-зависимость, необходимость Playwright и рациональный публичный XHR/API. Непроверенное помечать явно; отсутствие поля в выборке не доказывает отсутствие на всём сайте.

Аудит не должен останавливать работу со всеми поставщиками из-за одного проблемного домена. Не обходить CAPTCHA/авторизацию/защиты; сохранить ограничение и продолжить. Полный повтор аудита нужен при задаче на все сайты, а не при каждом изменении кода.
